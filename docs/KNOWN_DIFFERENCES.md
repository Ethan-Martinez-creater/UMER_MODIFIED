# 已知材料差异与阅读优先级

这些条目在背景阅读中已发现；本次仅登记，没有修订论文科学正文、重训模型或开展新的审稿。

## 已知差异

1. **论文 README 过时**：原目录 README 仍称实验和结论未完成；实际 main.tex 已包含这些章节。因此不原样发布旧 README，改用本仓库 manuscript/README.md 说明快照。
2. **文本辅助监督**：原稿方法公式把辅助文本 CE 写在均值 logits 上；架构记录与所读 model.py 实现对各受监督视图计算 CE。归档保留两者，没有静默修改其中任何科学定义。
3. **Set 编码描述**：原稿以 14 个 token 及两层聚合表达 Set 路径；所读 original_model.py 是每节点 14 维特征向量经 MLP 后，对节点做 mean/max pooling。需要区分论文符号表达和源码实际算子。
4. **历史研究状态**：十月初 BCR M1-E 的阶段性信息已经被后续 M1-F 关闭结论覆盖。八月材料的“全部失败/从未外部 API”等不能涵盖后续阶段。
5. **代码默认值与正式配置**：历史 run_fold.py 支持多种设置，并含 DeBERTa-v3-base 等默认值；正式 UMER 使用文档记载的 DeBERTa-v3-large 等冻结配置。不能直接把默认参数视为正式运行参数。公开副本仅替换了两个私有部署位置。
6. **审计与正文状态**：配套审计中“已标记”“计划采用”“待加入”等描述反映当时的写作状态，不保证已经同步到当前 TeX。PHEME 测试参与选择、MST 过滤 source-only、Ma-Weibo RRD-N 仅三折等限定应保留。
7. **汇总字段范围**：本仓库原始 summary JSON 保存 Accuracy、Weighted-F1、Macro-F1、Rumor-F1；Ma-Weibo Macro-P/R 来自配套审计和现稿，不假称六份 JSON 含有这些字段。

## 如何处理冲突

先注明所依据的材料、日期、任务及协议，再区分用户交接、已读源码、历史审计与实际原始结果。不要只依据“最新”字样覆盖有日期的证据；也不要用代码片段宣称所有正式检查点已经按同一版本核验。

main.tex 保留既有写法用于后续讨论；正式训练与模型评估没有在本次归档中执行。会议模板与历史参考文献核验不等于当前投稿选择或最新网页核验。
